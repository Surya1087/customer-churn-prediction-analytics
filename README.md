# Customer Churn Prediction & Business Analytics

An end-to-end customer churn project built with Python, SQL, classical machine learning, and Streamlit. It is designed to be easy to study in notebooks and still has a modular application workflow.

## Quick start (macOS)

```bash
cd customer-churn-prediction-analytics
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
pip install -r requirements.txt
```

The IBM Telco Customer Churn CSV is stored locally in `data/raw/` for development. It is excluded from Git commits. For a fresh clone, create the local output directories, then download the dataset using the link in `data/README.md`:

```bash
mkdir -p data/raw database models
```

Run the application workflow:

```bash
PYTHONPATH=src python scripts/prepare_data.py
PYTHONPATH=src python scripts/run_sql_analytics.py
PYTHONPATH=src python scripts/train_models.py
PYTHONPATH=src pytest -q
streamlit run app/streamlit_app.py
```

## Notebook workflow

For a cell-by-cell walkthrough, open:

```text
notebooks/Customer_Churn_Complete.ipynb
```

It includes data loading, SQL, EDA, graphs, preprocessing, all five models, tuning, evaluation, prediction, explainability, and K-Means segmentation. Standalone topic notebooks are also available in `folder2/`, and one notebook for each model is in `folder2/models/`.

## Architecture

Raw CSV → validation/cleaning → SQLite → SQL analytics; and raw CSV → stratified split → imputation/encoding/scaling pipeline → model comparison and tuning → saved artifact → Streamlit dashboard.

The training script compares DummyClassifier, Logistic Regression, Decision Tree, Random Forest, and XGBoost. Tuned candidates use cross-validated grid search. ROC-AUC is the primary selection criterion, with F1-score as a tie-breaker. The held-out test set is not used during tuning.

## Dataset attribution and limitations

The IBM Telco Customer Churn dataset is a publicly distributed IBM sample dataset. Check the source host's current usage terms before redistribution; this repository intentionally excludes the raw CSV. The data is observational and historical, so model signals are predictive associations rather than causal explanations.

## Main structure

```text
app/                         Streamlit dashboard
data/                        Dataset instructions and local raw data
database/                    Local SQLite database
notebooks/                   Notebook-first learning workflow
models/                      Saved model artifacts and metrics
scripts/                     Data preparation, SQL, and training commands
sql/                         Reusable SQL queries
src/churn_analytics/         Reusable Python modules
tests/                       Automated tests
```

## Outputs

- `database/churn.db`: local SQLite database
- `models/churn_pipeline.joblib`: selected fitted pipeline
- `models/metrics.json`: metrics generated by actual local training
- `sql/analytical_queries.sql`: business queries

Metrics in `models/metrics.json` are generated by the local training run and should be regenerated when dependencies, data, or training settings change.

## Limitations

This is an observational dataset. Churn patterns and feature importance indicate associations or predictive signals, not causal effects. Retention recommendations should be tested with controlled business experiments.

The current implementation selects the winning model using held-out test scores after training-only hyperparameter tuning. This introduces selection bias: those scores are not an unbiased final evaluation. Before presenting final benchmark results, model selection must be moved to training-only validation and followed by an independent final evaluation.
